1. HTML Document Format

HTML (HyperText Markup Language) defines the structure and meaning of webpage content. A modern document has one doctype declaration, one root <html> element, a metadata <head>, and a visible-content <body>. This structure is the foundation for every other section in this guide.

1.0 Core concepts and terminology

  1. <!DOCTYPE html> - document type declaration.
    • Tells the browser to use modern HTML standards mode.
    • It is not an HTML element, has no attributes, and has no closing tag.
    • Put it once, before <html>.
  2. <html lang="en"> - root element and language.
    • <html> wraps the complete HTML document.
    • lang identifies the main human language; examples: en, en-GB, bn, fr.
    • dir controls text direction independently: ltr, rtl, or auto.
  3. <head> - document configuration.
    • Holds metadata, title, stylesheets, icons, and suitable scripts.
    • It is not the container for visible page paragraphs or headings.
  4. <meta charset="UTF-8"> - character encoding.
    • meta supplies metadata; charset names the character encoding.
    • UTF-8 supports characters from a wide range of languages and symbols.
    • Place this early in <head>.
  5. <meta name="viewport" content="width=device-width, initial-scale=1">.
    • name="viewport" selects viewport configuration.
    • content contains comma-separated settings.
    • width=device-width matches the layout viewport to the device width.
    • initial-scale=1 starts at the normal zoom level; avoid disabling user zoom.
  6. <title> - document title.
    • Text between the tags appears in the browser tab and is used by bookmarks and search previews.
    • It is different from the visible <h1> heading.
  7. <body> - visible document content.
    • Contains the page’s content and semantic regions.
    • Common children include <header>, <nav>, <main>, <section>, and <footer>.
  8. <h1> through <h6> - heading levels.
    • <h1> is the highest level; <h6> is the lowest.
    • Choose levels by topic hierarchy, not by the font size you want.
  9. <p> - paragraph.
    • Groups a paragraph of prose.
    • Do not use it as a generic wrapper for unrelated layout elements.
  10. <a href="..."> - hyperlink.
    • <a> creates a link when it has an href.
    • href is the destination URL or URL fragment.
    • The content between the tags is the clickable link text.
  11. <img src="..." alt="..."> - image.
    • src gives the image resource location.
    • alt supplies a text alternative; describe meaningful images and use alt="" for decorative images.
    • <img> is a void element: it has no closing tag.
  12. </...> - closing tag.
    • Ends an element whose content is not void.
    • Nest elements in the correct order; close the most recently opened element first.

1.2 <!DOCTYPE html> - standards mode

The HTML5 doctype tells browsers to render the page in standards mode. It has no attributes and no closing tag.

<!DOCTYPE html>

1.3 <html lang> - root language

lang identifies the primary language of the page. Use a valid BCP 47 language tag: en, en-GB, bn, ar, and so on. Set dir="rtl" when the document’s base direction is right-to-left; language and direction are separate concepts.

<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>HTML Reference</title>
  </head>
  <body>
    <main>
      <h1>HTML Reference</h1>
      <p>A structured guide to modern HTML.</p>
    </main>
  </body>
</html>

1.4 <head> - document configuration

The head contains metadata, the title, stylesheets, icons, and scripts that configure the document. It should not contain ordinary visible page content.

1.5 <body> - page content

Put content intended for the page inside <body>. Organize it with semantic elements such as <header>, <nav>, <main>, <section>, <article>, <aside>, and <footer>.

1.6 Heading hierarchy

Use <h1> for the page’s main subject and descend through <h2> to <h6> for nested topics. Do not skip levels merely to obtain a smaller font; style heading appearance with CSS.

<main>
  <h1>Research Portal</h1>
  <section>
    <h2>Projects</h2>
    <section>
      <h3>Genome Analysis</h3>
      <h4>Quality Control</h4>
    </section>
  </section>
</main>

1.7 Complete minimal document

<!DOCTYPE html>
<html lang="en">
<head>

  <meta name="description" content="A concise description of this page.">

    <a href="/">Research Portal</a>
  </header>

    <p>Start exploring the portal.</p>
  </main>
  <footer>
    <small>© 2026 Research Portal</small>
  </footer>

</html>

2. Head & Metadata

The <head> configures how the browser and other services interpret a document. Metadata can describe the page, define character encoding, control viewport behavior, connect CSS, load scripts, and provide icons. Metadata does not replace visible headings or page content.

2.0 Core concepts and terminology

  1. <meta> - metadata element.
    • Supplies document information or browser instructions; it has no closing tag.
    • Its meaning is determined by attributes such as charset, name, and http-equiv.
  2. charset="UTF-8" - character encoding.
    • charset names the encoding used to decode the document.
    • UTF-8 is the standard choice for modern HTML.
  3. name="viewport" and content="..." - viewport configuration.
    • name identifies the kind of metadata.
    • content supplies its setting string.
    • Common values: width=device-width, initial-scale=1, minimum-scale, and maximum-scale; do not restrict zoom unnecessarily.
  4. name="description" - page summary.
    • content contains a concise, page-specific description.
    • Search engines may use it as a result snippet; it is not a guaranteed ranking control.
  5. name="author" - author metadata.
    • content contains the author or organization name.
    • It is informational, not a visible byline.
  6. name="robots" - crawler instructions.
    • Common directives include index, noindex, follow, and nofollow.
    • Combine directives in content, for example noindex, follow; use carefully because indexing behavior depends on crawler support.
  7. <link rel="stylesheet" href="..."> - external resource.
    • rel states the relationship; stylesheet means a CSS stylesheet.
    • href is the resource URL.
    • Other common rel values include icon, preconnect, and canonical.
  8. <style> - embedded CSS.
    • CSS rules go between its opening and closing tags.
    • Use it for page-specific rules; a separate .css file is usually easier to maintain across pages.
  9. <script src="..." defer> - JavaScript resource.
    • src points to the script file.
    • defer downloads while parsing and runs after parsing, preserving document order for classic external scripts.
    • async runs when ready without preserving order; type="module" enables JavaScript modules.
  10. <base href="..."> - base URL.
    • Changes how relative URLs in the document are resolved.
    • There should be at most one <base> element, and it belongs in <head>.

2.2 Character encoding - charset

Use UTF-8 and place the declaration near the beginning of the head so the browser can identify the encoding early.

<meta charset="UTF-8">

2.3 Responsive viewport - name and content

width=device-width matches the layout viewport to the device width. initial-scale=1 sets the initial zoom. Avoid disabling zoom with maximum-scale or user-scalable=no, because that can prevent users from enlarging content.

<meta name="viewport" content="width=device-width, initial-scale=1">

2.4 Description, author, and robots metadata

content contains the metadata value. Descriptions should summarize the specific page rather than repeat a site-wide slogan. noindex is a crawler instruction, not an access-control mechanism.

<meta name="description" content="Learn modern HTML elements, attributes, and accessible patterns.">
<meta name="author" content="Example Research Team">
<meta name="robots" content="index, follow">

2.5 Social sharing metadata

Open Graph properties influence previews on services that read them. Use absolute image and page URLs. Twitter/X cards may also use name="twitter:card" and related metadata.

<meta property="og:type" content="website">
<meta property="og:title" content="HTML Reference">
<meta property="og:description" content="A practical guide to modern HTML.">
<meta property="og:url" content="https://example.com/html-reference">
<meta property="og:image" content="https://example.com/images/html-cover.png">
<meta name="twitter:card" content="summary_large_image">

2.6 External resources - <link>

rel describes the relationship and href identifies the resource. media can limit a stylesheet to a media condition. crossorigin may be needed for certain cross-origin resources such as fonts.

<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="stylesheet" href="/css/site.css">
<link rel="preconnect" href="https://fonts.example-cdn.com">
<link rel="canonical" href="https://example.com/html-reference">

2.7 Internal CSS - <style>

Use <style> for small page-specific rules or prototypes. For maintainable sites, prefer an external stylesheet.

<style>
  :root {
    color-scheme: light dark;
  }

  body {
    font-family: system-ui, sans-serif;
    line-height: 1.6;
  }
</style>

2.8 JavaScript loading - defer, async, and modules

  • defer: downloads in parallel and executes after HTML parsing, preserving order among deferred classic scripts.
  • async: executes as soon as available; execution order is not guaranteed.
  • type="module": loads an ES module; modules are deferred by default.
  • Inline module scripts can use type="module" without src.
<script src="/js/site.js" defer></script>
<script type="module" src="/js/app.js"></script>

2.9 <base> - relative URL resolution

<base href> changes how relative URLs resolve across the document. It can unexpectedly affect links, images, and forms, so use it only when required and place it before elements containing relative URLs.

<base href="https://example.com/docs/">

  <meta property="og:title" content="HTML5 Reference">
  <meta property="og:description" content="Learn HTML elements and attributes.">

3. Global Attributes

Global attributes apply to most HTML elements. They provide identity, CSS hooks, language and direction, visibility, editing, focus, custom data, and accessibility-related configuration. An attribute is only useful when its behavior is appropriate for the element and user task.

3.0 Core concepts and terminology

  1. id="..." - unique element identifier.
    • Must be unique within the document.
    • Used by CSS #id, JavaScript selection, labels, and fragment links such as href="#contact".
  2. class="..." - reusable category.
    • Contains one or more space-separated class names.
    • Reuse classes across elements; CSS selects them with .class-name.
  3. style="..." - inline CSS declaration list.
    • Contains CSS property/value pairs, not a stylesheet selector.
    • Example: style="color: navy; font-size: 1rem;".
    • Prefer classes for reusable design and easier maintenance.
  4. title="..." - advisory information.
    • May be exposed as a tooltip by some browsers.
    • Do not put essential instructions only in title, because touch and keyboard access can be inconsistent.
  5. lang="..." - language of content.
    • Use a language tag such as en, bn, or en-GB.
    • Apply it to a nested element when a passage changes language.
  6. dir="ltr|rtl|auto" - text direction.
    • ltr means left-to-right; rtl means right-to-left.
    • auto lets the browser infer direction from text.
    • Direction is not the same thing as language.
  7. hidden - hidden state.
    • A Boolean attribute: its presence hides the element from normal rendering.
    • hidden="false" is still present and therefore does not mean false; remove the attribute to show the element.
  8. inert - inactive subtree.
    • Prevents interaction and focus within the element and removes it from the accessibility tree.
    • Use when a region should temporarily be unavailable, not merely visually hidden.
  9. data-* - custom data attributes.
    • Names begin with data-, for example data-product-id.
    • JavaScript reads them through element.dataset.productId.
    • Store application data, not secrets or authorization decisions.
  10. contenteditable="true|false|plaintext-only" - editable content.
    • true enables rich editing; plaintext-only limits editing to plain text where supported.
    • Editing in the browser does not automatically save data to a server.
  11. spellcheck="true|false" - spelling assistance preference.
    • Requests browser spellchecking behavior for editable text.
    • It is a hint and browser support or behavior may vary.
  12. translate="yes|no" - translation preference.
    • Indicates whether the element’s text should be translated by translation tools.
    • It does not itself perform translation.
  13. tabindex="..." - keyboard focus order.
    • 0 makes an element focusable in normal document order.
    • -1 allows programmatic focus but removes it from sequential Tab navigation.
    • Avoid positive values because they create confusing custom focus order.

3.2 id - unique identity

Use an id for a unique target, such as a fragment-link destination or a JavaScript hook. IDs must be unique within the document. Prefer CSS classes for styling multiple elements.

<section id="research">
  <h2>Research</h2>
</section>
<a href="#research">Go to research</a>

3.3 class - reusable grouping

An element can have multiple classes separated by spaces. Class names are case-sensitive in HTML selectors and should describe purpose rather than appearance where practical.

<article class="card featured">
  <h2 class="card__title">Genome report</h2>
</article>

3.4 style - inline CSS

style accepts CSS declarations. It is useful for exceptional one-off values, but repeated styling belongs in a stylesheet so it can be reused and maintained.

<p style="color: #174ea6; font-weight: 700;">
  Highlighted notice
</p>

3.5 title - advisory text

Browsers may show title as a tooltip. It is not reliably available to touch users and should not be the only label or instruction for an interactive control.

<abbr title="HyperText Markup Language">HTML</abbr>

3.6 lang and dir - language and direction

Set lang on the smallest element whose language differs from its parent. Use dir="auto" for user-entered text whose direction is not known in advance.

<p lang="bn">এটি বাংলা ভাষার একটি বাক্য।</p>
<p dir="rtl" lang="ar">هذا نص باللغة العربية.</p>
<bdi dir="auto">User supplied text</bdi>

3.7 hidden and inert

hidden hides content from normal rendering. inert keeps a subtree rendered but prevents focus and user interaction. Do not use either to conceal security-sensitive information; hidden content remains in the document.

<p hidden>This content is currently hidden.</p>
<div inert>
  <button type="button">Temporarily unavailable</button>
</div>

3.8 data-* - custom data

Custom data attributes are exposed through an element’s dataset property. Use them for small pieces of UI-associated data, not as a replacement for a database or secure storage.

<button type="button" data-product-id="P104" data-category="books">
  View product
</button>
const button = document.querySelector("[data-product-id]");
console.log(button.dataset.productId);
console.log(button.dataset.category);

3.9 contenteditable, spellcheck, and translate

contenteditable="true" enables rich editing; plaintext-only requests plain-text editing. Use a proper form control when collecting structured user input. Spell-check is a hint and may depend on browser settings.

<p contenteditable="true" spellcheck="true">
  Edit this paragraph.
</p>
<p translate="no">Bio-Matters</p>

3.10 tabindex - keyboard focus

  • tabindex="0" places a normally non-focusable element in natural tab order.
  • tabindex="-1" allows programmatic focus without adding it to sequential tab order.
  • Positive values reorder focus and should generally be avoided.
<main id="main-content" tabindex="-1">
  <h1>Page content</h1>
</main>

3.11 Complete global-attribute example

<section id="sample-panel" class="panel panel--editable" lang="en" dir="ltr"
         data-record-id="101" aria-labelledby="panel-title">
  <h2 id="panel-title">Editable project note</h2>
  <p contenteditable="true" spellcheck="true">
    Select this text and edit it.
  </p>
  <button type="button" data-action="save">Save note</button>
</section>

4. Text & Typography

HTML text elements express structure and meaning. CSS controls visual typography such as font family, size, weight, line height, spacing, and alignment. Use semantic elements for meaning rather than choosing tags solely because their default appearance looks suitable.

4.0 Core concepts and terminology

  1. <h1>–<h6> - heading hierarchy.
    • The number expresses structural level, not a request for a particular font size.
    • Use nested levels to represent sections and subsections.
  2. <p> - paragraph.
    • Groups a block of prose and provides paragraph semantics.
    • Use CSS margins to control spacing rather than inserting repeated <br> tags.
  3. <br> - line break.
    • Breaks a line within content such as an address or poem.
    • It is a void element; do not use it to create page layout gaps.
  4. <hr> - thematic break.
    • Represents a change of topic or scene, usually rendered as a horizontal rule.
    • Style its appearance with CSS.
  5. <strong> - strong importance.
    • Marks content with strong importance, seriousness, or urgency.
    • Browsers commonly render it bold, but the meaning is semantic.
  6. <em> - stress emphasis.
    • Marks a word or phrase that changes the emphasis of a sentence.
    • Browsers commonly render it italic; use CSS when italics are purely decorative.
  7. <b> and <i> - attention and alternate voice.
    • <b> draws attention without adding importance.
    • <i> marks an alternate voice, technical term, or idiomatic phrase; neither is a generic styling substitute.
  8. <mark> - relevant highlight.
    • Marks text relevant to the current context, such as a search match.
    • Use CSS to change highlight colors.
  9. <small> - side comments or fine print.
    • Suitable for legal notes, copyright, and disclaimers.
    • It does not mean “make any text smaller” as a layout technique.
  10. <del> and <ins> - edits.
    • <del> marks removed content; <ins> marks inserted content.
    • Optional cite gives a source URL and datetime records a machine-readable date/time.
  11. <sub> and <sup> - subscript and superscript.
    • Use for formulas, footnote markers, and mathematical notation where semantically appropriate.
    • They affect typographic placement, not the underlying text value.
  12. <abbr title="..."> - abbreviation.
    • The text is the shortened form; title may provide its expansion.
    • Do not rely on hover-only title text for essential information.
  13. <time datetime="..."> - date/time.
    • Visible text is for people; datetime supplies a machine-readable value.
    • Use valid date, time, or date-time formats.
  14. <span> and <div> - generic containers.
    • <span> is inline; <div> is block-level by default.
    • Add a meaningful class when CSS or JavaScript needs a hook; prefer semantic elements when they fit.

4.2 Headings and paragraphs

Use headings to organize a logical outline. Use paragraphs for prose. Do not use heading elements simply to make text larger.

<h1>Laboratory Handbook</h1>
<h2>Sample preparation</h2>
<h3>DNA extraction</h3>
<p>Prepare the sample using the validated protocol.</p>

Use <br> for a line break that is part of the content, such as an address or poem. Use <hr> when the topic or scene changes. Use CSS margins and padding for layout spacing.

<p>
  Research Building<br>
  12 Science Road<br>
  Dhaka
</p>
<hr>
<p>Next topic begins here.</p>

4.4 Importance, emphasis, and stylistic attention

<strong> communicates importance; <em> communicates stress emphasis. <b> draws attention without asserting importance, while <i> marks an alternate voice or technical convention.

<p><strong>Warning:</strong> Back up the database before migration.</p>
<p>You <em>must</em> verify the sample identifier.</p>
<p>Search for the <b>HTML</b> keyword.</p>
<p>The term <i>in vitro</i> is Latin.</p>

4.5 Highlighting, small print, and annotations

<mark> indicates relevance in the current context. <small> is for side comments or fine print. <u> should not be used as a generic underline style because underlines are commonly interpreted as links.

<p>Search result: <mark>responsive images</mark>.</p>
<p><small>Updated 16 November 2026. Terms may change.</small></p>
<p><u>Unusual spelling</u> is annotated here.</p>

4.6 Insertions, deletions, and no-longer-relevant text

Use <del> and <ins> when showing document edits. Use <s> when information is no longer accurate or relevant but is not a formal edit history.

<p>Old fee: <del datetime="2026-01-01">$50</del></p>
<p>Current fee: <ins datetime="2026-03-01">$40</ins></p>
<p><s>Registration is open</s> Registration has closed.</p>

4.7 Subscript and superscript

Use <sub> and <sup> for notation where the lowered or raised position is meaningful, such as chemical formulas, exponents, and footnote markers.

<p>Water: H<sub>2</sub>O</p>
<p>Area: x<sup>2</sup></p>

4.8 Abbreviations, dates, and machine-readable values

<abbr title> can provide an expansion. <time datetime> provides a machine-readable date/time. <data value> associates visible text with a machine-readable value.

<p><abbr title="HyperText Markup Language">HTML</abbr> structures pages.</p>
<time datetime="2026-11-16">16 November 2026</time>
<data value="SKU-104">Product 104</data>

4.9 Inline containers and wrapping

<span> has no semantic meaning by itself; use it as a styling or scripting hook. <wbr> marks a preferred optional line-break location for long strings.

<p>Current status: <span class="status status--ready">Ready</span></p>
<p>long-dataset-identifier<wbr>-with-many<wbr>-segments</p>

4.10 Complete semantic text example

<article>
  <h1>Water analysis</h1>
  <p><strong>Important:</strong> Verify the sample before testing.</p>
  <p>The measured value was <mark>7.2</mark> pH units.</p>
  <p>Water is represented by H<sub>2</sub>O.</p>
  <p>The result was updated on <time datetime="2026-11-16">16 November 2026</time>.</p>
  <p><small>Values are illustrative and not laboratory advice.</small></p>
</article>

5. Links & Navigation

The <a> element creates hyperlinks. Its href can identify a page, file, fragment, email address, telephone number, or other URL. The <nav> element groups major navigation links. Link text should describe the destination or action so it makes sense out of context.

5.0 Core concepts and terminology

  1. <a> - anchor element.
    • Creates a hyperlink when href is present.
    • Use meaningful link text that explains the destination or action.
  2. href="..." - destination.
    • Can be an absolute URL, relative path, fragment (#section), email (mailto:), or telephone (tel:).
    • href="#" is not a substitute for a button.
  3. Relative URLs.
    • about.html resolves relative to the current document/base URL.
    • /about/ starts from the site root.
    • ../images/photo.jpg moves up one directory.
  4. target="_blank" - new browsing context.
    • Requests that the destination open in a new tab or window.
    • Tell users when a link opens a new tab if that context change matters.
  5. rel="noopener" - opener isolation.
    • Prevents the opened page from controlling the originating page through window.opener.
    • Modern browsers generally apply this protection to _blank, but explicitly writing it can communicate intent.
  6. rel="noreferrer" - suppress referrer.
    • Prevents the destination from receiving the referring URL and also implies noopener.
    • Use only when suppressing referrer information is intended.
  7. rel="nofollow|sponsored|ugc" - link relationship hints.
    • nofollow indicates the site does not endorse or pass normal ranking credit.
    • sponsored identifies paid or sponsored links.
    • ugc identifies user-generated links.
  8. download - download hint.
    • Requests download behavior for eligible same-origin or permitted URLs.
    • Optional value suggests a filename; browser and cross-origin rules apply.
  9. mailto: and tel: - contact links.
    • mailto:name@example.com opens an email handler.
    • tel:+880... opens a calling handler on supported devices.
  10. <nav> and aria-current="page" - navigation context.
    • <nav> identifies a major navigation region.
    • aria-current="page" identifies the current page link for assistive technology.

5.2 Basic and relative links

Relative URLs resolve from the current document URL (or <base> if present). Common forms include about.html, ../index.html, /contact/, and #section-id.

<a href="about.html">About us</a>
<a href="../index.html">Parent folder home</a>
<a href="/contact/">Contact</a>
<a href="#resources">Jump to resources</a>

5.3 External links and new tabs

target="_blank" requests a new browsing context. Modern browsers generally imply noopener for _blank, but explicitly writing it documents the intent. Add noreferrer when the referrer should not be sent; it also implies noopener.

<a href="https://developer.mozilla.org/"
   target="_blank"
   rel="noopener noreferrer">
  Read the HTML documentation
</a>

5.4 rel values for link relationships

  • noopener: prevents access through window.opener.
  • noreferrer: suppresses the referrer header and implies noopener.
  • nofollow: signals that the site does not endorse the destination for ranking purposes.
  • ugc: identifies user-generated links.
  • sponsored: identifies paid or sponsored links.
  • external: identifies an external destination; it does not itself change browser behavior.
<a href="https://example.org" rel="external noopener">External resource</a>
<a href="https://example.org/community" rel="ugc nofollow">Community post</a>
<a href="https://example.org/partner" rel="sponsored nofollow">Sponsored partner</a>

5.5 Email and telephone links

mailto: opens a configured email handler. Query parameters such as subject and body can prefill a message. tel: uses a telephone URI; use an internationally formatted number where possible.

<a href="mailto:help@example.com?subject=Website%20question">Email support</a>
<a href="tel:+8801234567890">Call support</a>

5.6 Download links

The download attribute requests download behavior and can suggest a filename. It is generally subject to same-origin and browser security restrictions; a cross-origin server may need suitable headers.

<a href="/files/guide.pdf" download="html-guide.pdf">Download the guide</a>

5.7 Navigation landmarks and current page

Use <nav> for major navigation groups. aria-current="page" identifies the current page in a navigation set.

<nav aria-label="Primary navigation">
  <a href="/" aria-current="page">Home</a>
  <a href="/guides/">Guides</a>
  <a href="/contact/">Contact</a>
</nav>

6. Images

The <img> element embeds an image. src selects a resource and alt provides an equivalent for users who cannot see it. Responsive images use srcset and sizes; art direction uses <picture>. Use intrinsic width and height to reserve layout space, and lazy-load off-screen images rather than the primary above-the-fold image.

6.0 Core concepts and terminology

  1. <img> - image element.
    • Embeds an image in the document.
    • It is a void element and has no closing tag.
  2. src="..." - source URL.
    • Identifies the image file to load.
    • Use a correct relative or absolute path and provide a fallback strategy when appropriate.
  3. alt="..." - text alternative.
    • Describe the meaningful information conveyed by the image.
    • Use alt="" when an image is decorative or its information is already fully represented nearby.
  4. width and height - intrinsic dimensions.
    • Provide the intended display dimensions or aspect ratio hints.
    • Correct dimensions reserve layout space and reduce page shifting; CSS can still make the image responsive.
  5. loading="lazy|eager" - loading strategy.
    • lazy defers off-screen image loading.
    • eager loads without lazy deferral; use for important above-the-fold images when appropriate.
  6. decoding="async|sync|auto" - decode preference.
    • async allows decoding without blocking the next paint where possible.
    • auto lets the browser choose.
  7. fetchpriority="high|low|auto" - fetch priority hint.
    • high may help a critical hero/LCP image.
    • low can deprioritize noncritical images; do not mark every image high.
  8. srcset - candidate image sources.
    • Lists alternative image files with width (480w) or density (2x) descriptors.
    • The browser selects a suitable candidate.
  9. sizes - expected rendered slot width.
    • Gives the browser media-condition-based width information used with width-descriptor srcset.
    • Example: (max-width: 600px) 100vw, 50vw.
  10. <picture>, <source>, and media/type.
    • <picture> wraps alternative sources and a fallback <img>.
    • media selects by media condition; type indicates a format such as image/avif or image/webp.
  11. <figure> and <figcaption>.
    • <figure> groups self-contained media/content.
    • <figcaption> supplies its caption.
  12. <map>, <area>, usemap, shape, coords, and href.
    • <map name> defines an image map; <img usemap="#name"> connects it.
    • <area> defines a clickable region; shape may be rect, circle, poly, or default.
    • coords lists coordinate values for the selected shape; each area needs an accessible name.

     alt="Laboratory microscope"
     width="1200"
     height="800"
     style="max-width: 100%; height: auto;">

6.4 Loading, decoding, and priority

  • loading="lazy" defers off-screen images; do not lazy-load the likely Largest Contentful Paint/hero image.
  • decoding="async" allows decoding without blocking other rendering work.
  • fetchpriority="high" may help a critical image; use sparingly.
<img src="/images/article-figure.jpg"
     alt="Microscopy image of a tissue sample"
     width="1000"
     height="700"
     loading="lazy"
     decoding="async">

6.5 Responsive images - srcset and sizes

Use width descriptors such as 480w, 800w, and 1200w when files have different intrinsic widths. sizes describes the expected CSS slot width so the browser can choose an appropriate candidate.

<img
  src="/images/organism-800.jpg"
  srcset="
    /images/organism-480.jpg 480w,
    /images/organism-800.jpg 800w,
    /images/organism-1200.jpg 1200w
  "
  sizes="(max-width: 600px) 100vw, (max-width: 1000px) 80vw, 800px"
  alt="Microscopic view of the organism"
  width="1200"
  height="800"
  loading="lazy">

6.6 High-density displays - density descriptors

Use 1x, 2x, and similar density descriptors when candidates have the same intended CSS dimensions but different pixel densities. Do not mix density descriptors and width descriptors in one srcset.

<img src="/images/logo.png"
     srcset="/images/logo.png 1x, /images/logo@2x.png 2x"
     width="180"
     height="60"
     alt="Research Portal">

6.7 Art direction and modern formats - <picture>

Use <picture> when the crop or composition should change at a breakpoint, or when offering format alternatives. The fallback <img> is required and supplies the accessible text.

<picture>
  <source media="(max-width: 600px)" srcset="/images/lab-portrait-crop.jpg">
  <source type="image/avif" srcset="/images/lab.avif">
  <source type="image/webp" srcset="/images/lab.webp">
  <img src="/images/lab.jpg"
       alt="Researcher examining a laboratory sample"
       width="1200"
       height="800">
</picture>

6.8 Figure and caption

Use <figure> when an image, chart, illustration, code sample, or other content is a self-contained unit that can be referenced independently. <figcaption> labels the figure.

<figure>
  <img src="/images/genome-map.png"
       alt="Circular map of a bacterial genome showing annotated genes"
       width="1000"
       height="1000"
       loading="lazy">
  <figcaption>Annotated circular genome map.</figcaption>
</figure>

6.9 Decorative and functional images

A decorative image uses alt="". If an image is the only content inside a link or button, its alternative text should communicate the action or destination, not merely describe its appearance.

<img src="/images/divider.svg" alt="" width="900" height="12">

<a href="/profile/">
  <img src="/images/profile-icon.svg" alt="Open profile" width="32" height="32">
</a>

6.10 Image maps - <map> and <area>

Image maps create clickable regions. Each <area> needs an accessible name, usually with alt. Use image maps only when the interaction is appropriate and provide equivalent links or controls for keyboard and touch users.

<img src="/images/campus-map.png"
     alt="Campus map with selectable buildings"
     usemap="#campus-map"
     width="800"
     height="500">
<map name="campus-map">

        href="/buildings/library/" alt="Library">
  <area shape="circle" coords="400,220,70"
        href="/buildings/laboratory/" alt="Laboratory">
</map>

7. Audio & Video

<audio> and <video> embed media without third-party browser plugins. <source> offers alternative encodings; <track> supplies timed text such as captions, subtitles, chapters, and descriptions. Provide controls, captions for prerecorded video with meaningful audio, and a transcript where appropriate. Autoplay with sound is commonly blocked and can be disruptive.

7.0 Core concepts and terminology

  1. <audio> - audio player.
    • Embeds sound such as music, speech, or recordings.
    • Provide controls and meaningful fallback text.
  2. <video> - video player.
    • Embeds moving images and sound.
    • Set dimensions or responsive CSS to avoid unexpected layout changes.
  3. src and <source src type>.
    • src points to a media file.
    • Multiple <source> elements let the browser choose a supported format.
    • type gives the media MIME type, such as audio/mpeg or video/mp4.
  4. controls - native player interface.
    • Boolean attribute that asks the browser to show playback controls.
    • Presence enables it; controls="false" does not disable it.
  5. autoplay - automatic playback request.
    • Requests playback as soon as possible.
    • Browsers commonly block audible autoplay; do not rely on it.
  6. muted - initially muted.
    • Boolean attribute that starts media muted.
    • Muted autoplay may be allowed, but user preferences and browser policies apply.
  7. loop - repeat playback.
    • Boolean attribute that restarts media when it reaches the end.
  8. poster - video preview image.
    • Specifies an image shown before video playback begins.
    • It applies to <video>, not <audio>.
  9. preload="none|metadata|auto".
    • none asks the browser not to preload media.
    • metadata asks for basic information such as duration.
    • auto permits broader preloading; it remains a hint.
  10. <track kind src srclang label default>.
    • Adds timed text such as captions or subtitles.
    • kind values include captions, subtitles, descriptions, chapters, and metadata.
    • srclang identifies the language; label is the user-facing track name; default selects the default track.
  11. Captions and transcripts.
    • Captions include relevant speech and sound information.
    • A transcript provides an equivalent text version and is useful for accessibility and search.

8. Tables

HTML tables represent tabular data: information arranged in rows and columns. They are not page-layout tools. Use <caption> to name the table, <thead>, <tbody>, and <tfoot> to group rows, and <th> with appropriate scope to identify headers. Complex tables may require explicit header IDs and headers associations.

8.0 Core concepts and terminology

  1. <table> - tabular data.
    • Use for information with meaningful row/column relationships, not page layout.
    • Add a caption and appropriate header cells.
  2. <caption> - table title.
    • Describes the table’s subject.
    • Place it as a child near the beginning of <table>.
  3. <thead>, <tbody>, and <tfoot>.
    • Group header rows, body rows, and summary/footer rows.
    • These groups improve structure and can support styling and assistive technology.
  4. <tr> - table row.
    • Contains cells for one row.
    • Use <th> for a header cell and <td> for ordinary data.
  5. <th> - header cell.
    • scope="col" identifies a column header; scope="row" identifies a row header.
    • scope="colgroup" and scope="rowgroup" are available for grouped headers.
  6. <td> - data cell.
    • Holds the table’s ordinary data.
    • Use colspan or rowspan only when a cell genuinely spans columns or rows.
  7. colspan="n" and rowspan="n".
    • colspan spans multiple columns; rowspan spans multiple rows.
    • Values are positive integers within HTML’s permitted range.
  8. <colgroup> and <col>.
    • Define groups of columns for shared column-level styling or metadata.
    • span can specify how many columns a <col> represents.
  9. id and headers.
    • Give complex header cells unique IDs.
    • A data cell’s headers attribute lists the IDs of header cells that apply to it.
  10. Responsive table wrapper.
    • Place a wide table in a container with CSS overflow-x: auto.
    • Keep the table semantic; do not convert data tables into arbitrary div grids without a strong reason.

9. Lists

HTML provides ordered, unordered, and description lists. Choose the list type according to the relationship between items: sequence, unordered grouping, or term/description pairs. Lists can be nested, but keep nesting meaningful and avoid using lists solely for visual indentation.

9.0 Core concepts and terminology

  1. <ul> - unordered list.
    • Represents a group where item order is not meaningful.
    • Contains <li> elements.
  2. <ol> - ordered list.
    • Represents a sequence where order matters.
    • Contains <li> elements and supports numbering options.
  3. <li> - list item.
    • Represents one item in <ul>, <ol>, or <menu>.
    • It can contain text, links, paragraphs, and nested lists.
  4. type="1|A|a|I|i" on <ol>.
    • Selects decimal, uppercase alphabetic, lowercase alphabetic, uppercase Roman, or lowercase Roman markers.
    • CSS list-style-type offers additional presentation choices.
  5. start="n" - starting number.
    • Sets the first marker’s numeric value.
    • Useful when a numbered sequence continues across separate lists.
  6. reversed - descending order.
    • Boolean attribute that numbers the list in reverse.
    • The browser determines the starting number if start is omitted.
  7. value="n" on <li>.
    • Sets that item’s ordinal number in an ordered list.
    • Following markers continue from the changed value.
  8. <dl>, <dt>, and <dd>.
    • <dl> is a description list.
    • <dt> is a term/name; <dd> is its description or value.
    • Use for glossaries, metadata pairs, and similar name/value groups.
  9. <menu>.
    • Represents a list of commands or menu items.
    • It is not a replacement for every navigation bar; use <nav> with links for site navigation.
  10. Nested lists.
    • Put a nested <ul> or <ol> inside the relevant <li>.
    • Indentation and bullets are normally controlled with CSS.

10. Forms & Inputs

Forms collect and submit user data. <form> defines the submission boundary; <label> names controls; <input>, <select>, and <textarea> collect values; <button> triggers actions. Choose input types that match the data, validate on the server as well as in the browser, and explain errors in text.

10.0 Core concepts and terminology

  1. <form> - submission boundary.
    • Groups controls whose values are submitted together.
    • action identifies the destination; method selects the HTTP method.
  2. action="..." - submission URL.
    • Commonly a server endpoint such as /register.
    • If omitted, the browser submits to the current document URL.
  3. method="get|post" - submission method.
    • get places successful control values in the URL query string; use for searches and retrieval.
    • post sends values in the request body; commonly used for changes and uploads.
    • Neither method by itself encrypts data; use HTTPS.
  4. <label for="email"> and id="email".
    • for must match the control’s unique id.
    • Clicking the label focuses or activates its control and gives it an accessible name.
  5. <input type="..."> - single-line control.
    • Common types: text, email, password, search, tel, url, number, range, date, time, checkbox, radio, file, hidden, and submit.
    • Choose the type that matches the data so browsers can provide suitable keyboards and validation.
  6. name="..." - submitted field key.
    • The browser submits the control’s name/value pair.
    • A control without a name is generally not included in form submission.
  7. value="..." - control value.
    • Sets an initial or current value depending on control type.
    • For checkbox/radio, it is the value submitted when selected.
  8. required, disabled, readonly, and multiple.
    • These are Boolean attributes: presence enables the behavior.
    • required demands a value; disabled prevents interaction and submission; readonly prevents editing but generally remains submitted; multiple permits multiple values for supported controls.
  9. min, max, step, minlength, and maxlength.
    • Define validation boundaries for suitable input types.
    • step defines allowed increments; for numbers, step="0.5" allows half-unit steps.
  10. placeholder.
    • Shows a short hint while a control is empty.
    • It is not a replacement for a visible <label>.
  11. <textarea rows cols>.
    • Creates a multi-line text control.
    • Its initial text is placed between the tags, not in a value attribute.
  12. <select>, <option>, and <optgroup>.
    • <select> creates a choice control.
    • <option value> defines a selectable value; visible option text is shown to the user.
    • <optgroup label> groups related options.
  13. <fieldset> and <legend>.
    • <fieldset> groups related controls; <legend> names the group.
    • Useful for radio groups and multi-part questions.
  14. <button type="submit|button|reset">.
    • submit submits the form; button has no default form action; reset restores initial values.
    • Always specify type to avoid accidental submission.
  15. <datalist>, <output>, <progress>, and <meter>.
    • <datalist> supplies suggestions to a compatible input.
    • <output> represents a calculated result.
    • <progress> represents task completion; <meter> represents a measurement within a known range.

11. Semantic Page Structure

Semantic elements describe the role of page regions. They improve navigation for assistive technology, make source code easier to understand, and provide a meaningful structure for search engines and other tools. Choose an element based on the content’s role, not its default visual style.

11.0 Core concepts and terminology

  1. <header> - introductory region.
    • Usually contains a page or section title, logo, or introductory tools.
    • It is not limited to the top of the whole page; an article can have its own header.
  2. <nav> - major navigation.
    • Contains a significant group of navigation links.
    • Not every group of links needs to be wrapped in <nav>.
  3. <main> - primary page content.
    • Contains the central content unique to the page.
    • A document should normally have one main content region that is not hidden.
  4. <section> - thematic section.
    • Groups content around a topic and usually has a heading.
    • Do not use it merely as a styling wrapper when <div> is more accurate.
  5. <article> - independently meaningful composition.
    • Suitable for a post, news story, comment, or other reusable standalone item.
    • It may have its own heading, header, and footer.
  6. <aside> - complementary content.
    • Contains tangential or supporting material such as related links or side notes.
    • Its relationship to the surrounding content should be clear.
  7. <footer> - closing information.
    • May contain author details, copyright, related links, or contact information.
    • Like <header>, it can belong to a page or a sectioning element.
  8. <address> - contact information.
    • Provides contact details for the nearest article or body context.
    • It is not a generic wrapper for any postal address.
  9. <search> - search/filter region.
    • Identifies a region containing search or filtering controls.
    • Pair controls with labels and an understandable submit action.
  10. <hgroup>.
    • Groups a heading with related secondary content such as a subtitle.
    • Use only for heading-related grouping, not as a general layout container.

    <h1 id="projects-heading">Projects</h1>

12. Interactive Elements

Native interactive HTML elements provide keyboard and browser behavior without requiring custom JavaScript for basic operation. Use <details> for disclosure, <dialog> for modal or non-modal dialogs, and buttons for actions. Use ARIA only when native HTML does not already provide the required semantics.

12.0 Core concepts and terminology

  1. <details> - disclosure widget.
    • Provides content the user can expand or collapse.
    • The browser supplies the disclosure behavior.
  2. <summary> - disclosure label.
    • Must be the first summary/legend child of <details>.
    • Its text describes the content that will be revealed.
  3. open - initially expanded state.
    • Boolean attribute on <details>; presence opens the disclosure.
    • Remove it to start collapsed.
  4. <dialog> - dialog window.
    • Represents a dialog or interactive modal surface.
    • Use its built-in methods through JavaScript when opening and closing programmatically.
  5. showModal() and close().
    • showModal() opens a modal dialog and places it in the top layer.
    • close() closes it; provide a visible close/cancel control.
  6. method="dialog" on a form inside a dialog.
    • Submitting closes the dialog rather than sending a normal network form request.
    • Read the dialog’s returnValue when the choice matters.
  7. Popover attributes: popover, popovertarget, and popovertargetaction.
    • popover marks an element as a popover.
    • popovertarget connects a button to the popover’s id.
    • popovertargetaction can request show, hide, or toggle.
  8. <button> - user action.
    • Use for actions such as opening a dialog, toggling a menu, or submitting a form.
    • Use <a> for navigation to another resource.
  9. Keyboard and focus behavior.
    • Ensure controls are keyboard operable and have visible focus.
    • Do not create clickable <div> elements when a native button is appropriate.

  <h2 id="dialog-title">Project information</h2>

  <p>Choose a project before exporting a report.</p>
  <button type="button" popovertarget="help-popover"
          popovertargetaction="hide">Close</button>
</div>

Use type="button" for actions that should not submit a surrounding form. Use type="submit" to submit and type="reset" to reset. A disabled button cannot be activated.

<button type="button" disabled>Unavailable</button>

13. Embedded Content

Embedded content places external documents, browsing contexts, or graphics inside a page. Embeds can introduce security, privacy, accessibility, and performance concerns. Use the narrowest permissions necessary, provide titles for frames, and prefer native HTML when it can represent the content directly.

13.0 Core concepts and terminology

  1. <iframe> - nested browsing context.
    • Embeds another HTML page inside the current page.
    • src identifies the page; title describes the frame to assistive technology.
  2. width and height on <iframe>.
    • Set the frame’s initial dimensions.
    • CSS can make it responsive; preserve an appropriate aspect ratio for video embeds.
  3. loading="lazy".
    • Defers loading an off-screen iframe until it approaches the viewport.
    • Avoid lazy loading a frame that is immediately needed at the top of the page.
  4. sandbox.
    • Applies restrictions to the embedded page.
    • Add only the tokens required, such as allow-scripts or allow-forms; combinations can weaken isolation.
  5. allow.
    • Delegates selected browser capabilities, such as fullscreen or camera, subject to browser and policy restrictions.
    • Grant only capabilities the embed genuinely needs.
  6. referrerpolicy.
    • Controls how much referrer information is sent when fetching the embedded resource.
    • Choose a policy appropriate to the privacy needs of the page.
  7. <embed> and <object>.
    • Embed external resources or content handled by browser plugins/viewers.
    • Prefer modern, accessible alternatives where possible; support depends on resource type and browser.
  8. <svg> - scalable vector graphics.
    • Defines resolution-independent vector shapes.
    • Use viewBox to define the internal coordinate system; provide accessible naming when the graphic conveys meaning.
  9. <canvas> - script-drawn bitmap surface.
    • JavaScript draws pixels into the canvas.
    • Supply fallback content and an equivalent accessible description or interaction.

14. Code & Technical Text

HTML includes elements for code samples, keyboard input, program output, variables, and preformatted text. These elements communicate technical meaning; CSS controls syntax highlighting and visual styling. Escape reserved characters such as < and & when writing code as text in HTML.

14.0 Core concepts and terminology

  1. <code> - code fragment.
    • Marks a short piece of computer code, such as const total = 3.
    • It conveys code semantics; CSS controls the font appearance.
  2. <pre> - preformatted text.
    • Preserves whitespace and line breaks.
    • Commonly wraps a multi-line code sample together with <code>.
  3. <pre><code class="language-js">.
    • <pre> preserves formatting; <code> marks the content as code.
    • class="language-js" is a convention used by syntax highlighters, not a built-in HTML language switch.
  4. <kbd> - keyboard/user input.
    • Marks keys or input the user should enter.
    • Examples include Ctrl, Enter, or a command typed at a prompt.
  5. <samp> - program output.
    • Marks sample output from a program or system.
    • Keep input and output distinguishable in documentation.
  6. <var> - variable.
    • Marks a mathematical or programming variable name.
    • It is semantic markup, not a declaration of a real variable.
  7. Escaping code characters.
    • In HTML text, write &lt; for <, &gt; for >, and &amp; for &.
    • This prevents code examples from being parsed as actual HTML tags.
  8. Syntax highlighting.
    • HTML alone does not colorize code.
    • A CSS/JavaScript library can interpret language classes; do not assume language-js works without a highlighter.

15. Quotations & Semantic Information

Quotation elements identify quoted material and its source. Other semantic elements describe citations, definitions, contact details, edits, and directional text. Use the element that reflects the content relationship rather than relying on default italics or indentation.

15.0 Core concepts and terminology

  1. <blockquote> - extended quotation.
    • Marks a quoted section, generally presented as a block.
    • cite may provide the source URL; visible attribution should still be included when appropriate.
  2. <q> - short inline quotation.
    • Marks a quotation within a sentence.
    • Browsers may add quotation marks automatically; avoid manually duplicating them.
  3. <cite> - title of a creative work.
    • Identifies the title of a book, article, film, song, or other creative work.
    • It is not intended merely to wrap a person’s name as the source author.
  4. <dfn> - defining instance.
    • Marks the term being defined in its surrounding context.
    • Provide the definition in nearby text.
  5. <bdi> - bidirectional isolation.
    • Isolates a short unknown-direction text fragment, useful for user-generated names in mixed-direction text.
    • It prevents the fragment’s direction from affecting surrounding text.
  6. <bdo dir="..."> - bidirectional override.
    • Forces text direction with dir="ltr" or dir="rtl".
    • Use only when an intentional override is needed.
  7. <data value="...">.
    • Connects human-readable text to a machine-readable value.
    • value holds the programmatic representation.
  8. <time datetime="...">.
    • Marks a date or time and supplies a machine-readable datetime value.
    • The visible text can be formatted naturally for readers.
  9. <ins> and <del>.
    • Mark inserted and deleted text.
    • Optional datetime and cite attributes can record when and why the edit occurred.

<cite> identifies the title of a work, such as a book, report, film, or paper. Use normal text or a link for the author’s name.

Use <dfn> at the defining instance of a term. The surrounding text should provide the definition.

15.6 Bidirectional text - <bdi> and <bdo>

<bdi> isolates text whose direction may be unknown. <bdo> deliberately overrides the direction of its contents and should be used only when that override is intended.

<p>Sample: <data value="SMP-001">Sample 001</data></p>
<p>Previous title: <del>Draft report</del> New title: <ins>Final report</ins>.</p>

16. Accessibility

Accessible HTML makes content and interactions usable by people with different sensory, motor, cognitive, and language needs. Start with semantic HTML, meaningful labels, keyboard access, sufficient contrast, visible focus, text alternatives, and clear error messages. ARIA supplements native semantics; it does not repair fundamentally incorrect structure.

16.0 Core concepts and terminology

  1. alt - image text alternative.
    • Communicates the information or function of an image to people who cannot see it.
    • Decorative images should usually use an empty value alt="", not omit the attribute.
  2. <label for> and control id.
    • The for value must exactly match the control’s id.
    • This creates a programmatic label and a larger clickable target.
  3. <fieldset> and <legend>.
    • Group related controls and provide a group name.
    • Especially useful for radio buttons and related checkbox sets.
  4. required, min, max, pattern, and length constraints.
    • Provide native input validation.
    • Explain requirements in visible text; browser validation messages alone may not explain complex rules.
  5. aria-label.
    • Supplies an accessible name when a visible label is not available.
    • Prefer a visible <label> for form controls whenever possible.
  6. aria-labelledby.
    • Names an element using the text content of one or more other element IDs.
    • Every referenced ID must exist.
  7. aria-describedby.
    • Associates supplementary help or error text with a control.
    • It adds a description, not the control’s primary name.
  8. aria-live="polite|assertive".
    • Announces dynamic updates to assistive technologies.
    • polite waits for a suitable pause; assertive interrupts and should be reserved for urgent updates.
  9. aria-invalid="true|false" and aria-errormessage.
    • Communicate invalid state and identify the related error text where supported.
    • Keep the error message visible and associated with the relevant control.
  10. Keyboard access and focus.
    • All actions must work without a mouse.
    • Use native links and buttons, preserve logical focus order, and make focus indicators visible.
  11. ARIA rule of thumb.
    • Prefer correct native HTML first.
    • ARIA changes accessibility semantics; it does not automatically add keyboard behavior or functionality.

17. HTML + CSS Integration

HTML provides structure and semantics; CSS controls presentation and layout. CSS can be written inline, embedded in <style>, or loaded from an external stylesheet. For real projects, external CSS is usually easiest to maintain. Use classes for reusable styling and reserve IDs for unique targets.

17.0 Core concepts and terminology

  1. <link rel="stylesheet" href="styles.css">.
    • Loads an external CSS file.
    • rel="stylesheet" identifies the resource type; href is the file path.
    • A common project location is css/styles.css.
  2. <style>...</style>.
    • Holds CSS rules inside the HTML document’s head.
    • Useful for a small page-specific stylesheet; external files are easier to reuse.
  3. style="property: value;".
    • Adds declarations directly to one element.
    • Example: style="color: navy; font-size: 1rem;".
    • Inline style has high cascade precedence and is harder to maintain; use classes for shared styling.
  4. CSS rule anatomy: selector { property: value; }.
    • Selector identifies the elements to style.
    • Property is the feature, such as color.
    • Value sets the chosen result, such as navy.
    • Braces enclose declarations; semicolons separate declarations.
  5. class="card" and .card.
    • HTML class attribute assigns a reusable name.
    • CSS .card selects every element with that class.
  6. id="main" and #main.
    • HTML id identifies one element.
    • CSS #main selects that element; prefer classes for reusable styles.
  7. font-family.
    • Lists preferred fonts from left to right, then fallback families.
    • Example: font-family: Arial, Helvetica, sans-serif;.
    • Alternatives include Georgia, 'Times New Roman', serif, Verdana, sans-serif, and system UI stacks.
  8. font-size, font-weight, font-style, and line-height.
    • font-size sets text size (1rem, 16px, 120%).
    • font-weight controls thickness (400, 600, 700, normal, bold).
    • font-style commonly uses normal or italic.
    • line-height controls line box height (1.5 is a common body-text value).
  9. color and background-color.
    • color sets foreground text color.
    • background-color sets the element background.
    • Values may be named colors, hex (#123456), RGB/RGBA, or HSL/HSLA.
  10. margin, padding, and border.
    • margin is space outside the border.
    • padding is space between content and border.
    • border draws the edge; common syntax: 1px solid #ccc.
  11. display.
    • Common values: block, inline, inline-block, flex, grid, and none.
    • none removes the element from layout; use the hidden attribute when the content is semantically hidden.
  12. Flexbox and Grid.
    • display: flex lays items along a main axis; justify-content aligns on that axis and align-items on the cross axis.
    • display: grid creates rows and columns; grid-template-columns defines column tracks and gap sets spacing.
  13. Responsive CSS.
    • @media (max-width: 600px) applies rules at a viewport condition.
    • Relative units include %, rem, em, vw, and vh.
    • max-width: 100% helps media fit its container.
  14. CSS custom properties.
    • Define with --name: value and read with var(--name).
    • Example: :root { --brand: #2457a6; }.

18. HTML + JavaScript Integration

HTML defines the interface and content; JavaScript adds behavior and dynamic updates. Use <script src> for external files, defer for classic scripts that need the parsed document, and type="module" for modern module-based code. Prefer event listeners and DOM APIs over inline event-handler attributes.

18.0 Core concepts and terminology

  1. <script src="app.js" defer></script>.
    • script loads or contains JavaScript.
    • src points to the external file; defer waits until HTML parsing finishes before running a classic external script.
    • Put the file path relative to the HTML document.
  2. document.
    • Browser object representing the current HTML document.
    • JavaScript uses it to find and change page elements.
  3. document.querySelector("...").
    • Selects the first element matching a CSS selector.
    • Examples: #status selects an ID; .card selects a class; button selects a button.
  4. document.querySelectorAll("...").
    • Selects all matching elements and returns a NodeList.
    • Use iteration such as forEach to process each result.
  5. const and let.
    • const declares a binding that cannot be reassigned.
    • let declares a binding that can be reassigned.
    • Neither keyword automatically makes an object deeply immutable.
  6. addEventListener("click", callback).
    • Registers a function to run when an event occurs.
    • Common events include click, input, change, submit, and keydown.
  7. event and event.target.
    • The event object describes the event.
    • target is the element where the event originated; currentTarget is the element whose listener is running.
  8. textContent.
    • Reads or sets text content without interpreting it as HTML.
    • Prefer it for inserting untrusted text.
  9. innerHTML.
    • Reads or parses HTML markup inside an element.
    • Do not insert untrusted user content into it; this can create cross-site scripting vulnerabilities.
  10. setAttribute() and properties.
    • setAttribute("name", "value") changes an HTML attribute.
    • For common form properties, direct properties such as input.value or checkbox.checked are often clearer.
  11. classList.add/remove/toggle/contains.
    • Adds, removes, toggles, or tests CSS classes.
    • Use classes to switch visual states without building style strings.
  12. Form submit event and preventDefault().
    • Listen for submit on the form, not only click on its submit button.
    • preventDefault() stops the browser’s normal submission so JavaScript can validate or send data.
  13. FormData(form).
    • Collects successful form controls into key/value entries.
    • Controls need name attributes; disabled controls are not included.
  14. dataset.
    • Reads data-* attributes as strings.
    • data-user-id becomes element.dataset.userId.
  15. JSON.
    • JSON.stringify(value) converts a JavaScript value to JSON text.
    • JSON.parse(text) parses JSON text; handle invalid input and never treat JSON as executable code.
  16. Security and reliability.
    • Validate data on the server even if browser validation exists.
    • Prefer textContent for text, handle network errors, and do not store secrets in client-side JavaScript.

18.11 JavaScript security and reliability

  • Treat all user-provided data as untrusted.
  • Prefer textContent over innerHTML for plain text.
  • Validate on the server; browser validation can be bypassed.
  • Do not put secrets, API private keys, or passwords in frontend JavaScript.
  • Handle network failures and asynchronous states.
  • Keep scripts in external files for caching, testing, and maintenance.

19. Deprecated / Legacy HTML

Some older HTML elements and attributes remain recognized by browsers for compatibility but should not be used in new projects. Replace presentation-only markup with semantic HTML and CSS. Deprecated markup is not necessarily removed from browsers, but relying on it creates inconsistent, inaccessible, or difficult-to-maintain code.

19.0 Core concepts and terminology

  1. Deprecated/obsolete elements.
    • Old presentation elements such as <font>, <center>, and <strike> should not be used in new pages.
    • Replace their presentation with CSS and preserve the content’s semantic meaning.
  2. <font face color size>.
    • face selected a font family, color selected text color, and size selected a legacy size scale.
    • Modern replacement: CSS font-family, color, and font-size.
  3. <center>.
    • Historically centered content.
    • Modern replacement: CSS text-align: center for inline content or layout rules such as Flexbox/Grid for elements.
  4. <strike> and <s>.
    • <strike> is obsolete.
    • <s> means content is no longer accurate or relevant; use <del> when text was specifically deleted from a document.
    • Use CSS text-decoration: line-through only for purely visual styling.
  5. <acronym>.
    • Obsolete element for acronyms.
    • Use <abbr title="..."> for abbreviations and provide an expansion where useful.
  6. Presentational table attributes.
    • Old attributes such as align, bgcolor, border, cellpadding, and cellspacing are obsolete for presentation.
    • Use CSS properties such as text-align, background-color, border, padding, and border-spacing.
  7. <marquee> and <blink>.
    • Non-standard/obsolete motion effects with poor accessibility.
    • Avoid flashing or continuously moving content; if motion is essential, provide user control and respect reduced-motion preferences.
  8. Legacy alignment attributes.
    • Attributes such as align on many elements should be replaced with CSS layout and text alignment.
    • Do not confuse HTML attributes that carry semantic data with CSS presentation.
  9. Migration process.
    • Identify the meaning and purpose of the old markup first.
    • Replace presentation with CSS, use semantic HTML for meaning, and test keyboard access and responsive behavior.

Appendix C. Final Development Checklist

Document structure

  • One <!DOCTYPE html> declaration at the top.
  • One <html> root with an appropriate lang.
  • UTF-8 charset and responsive viewport metadata.
  • A meaningful, unique <title> for each page.
  • Semantic header, navigation, main, and footer regions where appropriate.

Content and semantics

  • Heading levels follow a logical hierarchy.
  • Paragraphs, lists, quotations, and tables use the correct semantic elements.
  • Tables represent data, include captions, and identify headers.
  • Links have descriptive text and buttons perform actions.
  • Images have suitable alternative text.

Forms and interaction

  • Every form control has an accessible label.
  • Related controls are grouped with fieldset and legend.
  • Input types and validation constraints match the data.
  • Buttons inside forms have explicit types.
  • Keyboard operation and visible focus are supported.
  • Dynamic status and error messages are accessible.

Media and performance

  • Images have intrinsic dimensions.
  • Responsive image candidates are appropriate for actual slot sizes.
  • Off-screen images and embeds use lazy loading where suitable.
  • Video captions and transcripts are provided where needed.
  • Autoplay is avoided unless justified and user-friendly.

CSS and JavaScript

  • Reusable styling is in external CSS.
  • Font stacks include generic fallbacks.
  • Layout adapts to small screens and zoom.
  • Reduced-motion preferences are respected.
  • JavaScript is loaded with an appropriate strategy.
  • Untrusted content is inserted as text, not unsafe HTML.
  • Client-side validation is backed by server-side validation.

Modernization and security

  • Deprecated presentational tags and attributes are replaced.
  • External new-tab links use appropriate rel values.
  • Iframes have titles and restrictive permissions.
  • No secrets are embedded in client-side code.
  • HTML is validated and tested in multiple browsers.

End of guide. This reference is intended as a learning and implementation aid. Browser behavior, accessibility support, and security requirements should be tested against the actual application and target browsers.
